# Eval-набор AI-ассистента

Eval-набор фиксирует типовые запросы к shopping assistant и проверяет качество
ответов одинаково для разных провайдеров, моделей и версий prompt.

## Состав набора

Сценарии находятся в `tests/evals/assistant/cases.json`. Каждый сценарий
содержит:

- `query` — типовой пользовательский запрос;
- `catalog_products` — фиксированный каталог, доступный модели;
- `allowed_product_ids` — допустимые рекомендации;
- `forbidden_product_ids` — неподходящие или запрещённые рекомендации.

Зафиксированный проходящий запуск находится в
`tests/evals/assistant/runs/baseline.json`.

## Формат запуска

Результат провайдера сохраняется в JSON:

```json
{
  "metadata": {
    "provider": "provider-code",
    "model": "model-name",
    "prompt_version": "v2"
  },
  "results": [
    {
      "case_id": "blue-speaker-budget",
      "message": "Ответ пользователю",
      "searched_product_ids": [101, 102],
      "selected_product_ids": [101],
      "mentioned_product_ids": [101],
      "product_card_ids": [101]
    }
  ]
}
```

`searched_product_ids` фиксирует результаты catalog tool,
`selected_product_ids` — структурированный выбор модели,
`mentioned_product_ids` — товары, упомянутые в тексте ответа,
`product_card_ids` — карточки, реально возвращённые клиенту.

При смене prompt необходимо увеличивать `OPENAI_PROMPT_VERSION` и записывать
новое значение в metadata запуска. Для другого адаптера используются его код и
фактическая модель.

## Метрики

Оценщик вычисляет четыре детерминированные метрики:

| Метрика | Условие прохождения |
| --- | --- |
| `grounding` | Найденные товары входят в фиксированный каталог, выбранные и упомянутые товары входят в результаты поиска |
| `relevance` | Выбран хотя бы один допустимый товар либо ничего не выбрано, когда допустимых товаров нет |
| `forbidden_recommendations` | Среди выбранных и упомянутых товаров нет запрещённых |
| `no_hallucinated_cards` | Карточки точно соответствуют выбранным товарам и входят в результаты поиска |

Неполный результат сценария проваливает все проверки.

## Запуск и сравнение

Проверить один запуск:

```bash
php scripts/evaluate-assistant.php path/to/candidate.json
```

Сравнить запуск после смены провайдера, модели или prompt с baseline:

```bash
php scripts/evaluate-assistant.php \
  path/to/candidate.json \
  tests/evals/assistant/runs/baseline.json
```

Команда печатает metadata обеих конфигураций, значения метрик и дельты. Любой
проваленный сценарий или отрицательная дельта завершает команду с ненулевым
кодом.

CI выполняет `composer assistant-eval` на зафиксированном baseline. Эта
детерминированная проверка защищает формат набора и логику оценивания без
сетевых вызовов, стоимости API и нестабильности live-моделей. Результаты
live-запусков сохраняются отдельными JSON-артефактами и сравниваются той же
командой перед сменой production-конфигурации.
